# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm start          # Start Expo dev server (choose platform interactively)
npm run ios        # Start on iOS simulator
npm run android    # Start on Android emulator
npm run web        # Start web version

npx tsc --noEmit  # Type-check (no build scripts configured)
```

No lint or test scripts are configured.

## Architecture

### Stack
- **React Native + Expo 54** (targets iOS, Android, Web via React Native Web)
- **Expo Router 6** for file-based routing under `app/`
- **Zustand 5** for global state with localStorage persistence
- **Supabase** for auth (email + Google OAuth) and user data sync
- **Anthropic SDK** for the in-app "Ask Claude" AI chat feature
- **TypeScript strict mode** with path alias `@/*` → `./src/*`

### Navigation
Custom React Context stack navigator (`src/navigation/`) rather than Expo Router's built-in navigation. `App.tsx` wraps everything in an `AuthGate` component that routes between onboarding and main flows based on Supabase session state. Screen names: `welcome`, `setup`, `home`, `timeline`, `task`, `calendar`, `profile`, `todos`, `ask`, `documents`.

### State (Zustand Store)
`src/store/useAppStore.ts` is the single source of truth. It holds:
- Onboarding inputs (origin, destination, pet type/name, airline, travel date, pet size)
- Task progress (completions, in-progress flags, user notes, appointment dates)
- Personal data (todos, documents as base64, calendar entries, pet photo as base64)
- Computed timeline (generated by the engine)
- Loaded rulesets and app config

The store auto-syncs to Supabase with a 3-second debounce (`src/lib/userDataSync.ts`).

### Timeline Engine
`src/engine/timeline.ts` — the core business logic. `buildTimeline()` performs a topological sort on a DAG of travel tasks, resolving timing constraints to produce ordered task cards with status labels (`completed`, `in_progress`, `overdue`, `due_soon`, `in_window`, `upcoming`, `blocked`, `milestone_reached`, `milestone_pending`).

Task timing types: `before_travel` (N days before departure), `after_task` (N days after another task completes), `before_task` (N days before another task), `anytime`.

### Configuration / Rulesets
`config/rules/` contains JSON rulesets that define travel requirements per route+pet combination. Rulesets support inheritance (`extendsRuleset`), overrides (`overrideTasks`), and additions (`additionalTasks`). `src/engine/configLoader.ts` loads bundled rulesets and can fetch updated versions remotely via a manifest (with fallback to bundled on timeout).

Type definitions for the rules engine live in `src/types/rules.ts`.

### Design System
`src/design/tokens.ts` — centralized colors, border-radius, and shadow values. Use these instead of hardcoded values in StyleSheets.

### Environment Variables
Required in `.env.local`:
- `EXPO_PUBLIC_ANTHROPIC_KEY` — Anthropic API key (used in Ask Claude screen)
- `EXPO_PUBLIC_SUPABASE_URL` — Supabase project URL
- `EXPO_PUBLIC_SUPABASE_ANON_KEY` — Supabase anon key
